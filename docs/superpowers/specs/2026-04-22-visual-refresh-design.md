# CitationClaw 全站视觉换肤设计

日期：2026-04-22

## 目标

在不删除任何现有功能、不改变现有页面主要结构、不改动现有中文文案语义的前提下，对 CitationClaw 当前 Web 界面进行一次全站视觉换肤。目标风格参考用户提供的学术工作台界面：白底、冷灰层次、蓝色强调、方正卡片、克制的层级感。

本次工作是样式改造，不是产品重设计。页面的功能入口、交互逻辑、字段名称、接口契约、任务流程、结果渲染机制必须保持兼容。

## 范围

### 在范围内

- 全局视觉变量：颜色、字体、阴影、边框、留白、圆角、背景层次
- 顶部导航、页宽容器、页脚、标题区的视觉重做
- 卡片、按钮、输入框、表单区块、状态标签、表格外观、分页、警告提示、空状态的样式统一
- `index.html`、`config.html`、`task.html`、`results.html` 中少量非功能性包装结构调整，用于承载统一样式
- 保留现有日志区域功能的前提下，对日志外框和周边卡片样式进行统一

### 不在范围内

- 不删除首页、配置页、任务页、结果页中的任何现有功能模块
- 不更换为新的信息架构，不做页面模块重排
- 不修改 `main.js`、`websocket.js` 中的业务逻辑
- 不修改 FastAPI 路由、接口结构、模板传参与数据流
- 不把中文文案替换为英文或中英混排文案
- 不把结果页核心表格强行改造成完全不同的展现模型

## 设计原则

### 1. 视觉语言统一

四个页面都必须归入同一套视觉系统，而不是每页各自换皮。用户进入任一页面时，应明显感知到这是一套连续的研究工作台界面。

### 2. 结构保持稳定

本次只允许视觉层升级，不允许通过大规模重排布局来“制造新设计”。页面原有使用习惯应尽量保持稳定。

### 3. 功能优先于造型

任何样式方案如果会削弱表单可读性、日志可读性、状态辨识度、表格可扫描性，都必须回退到更稳妥的实现。

### 4. 浅色主界面，深色仅用于日志

整体视觉采用浅色学术工作台体系。深色高对比区域只保留在日志/终端类模块，用于维持长文本输出的可读性。

## 视觉系统

### 色彩

- 主背景：接近白色的冷灰底色，用于页面主体与大面积背景
- 卡片背景：纯白
- 主边框：低对比灰蓝色细边框
- 主强调色：中高饱和蓝色，用于激活态、主按钮、链接、进度与重点信息
- 次级文字：中性灰蓝
- 成功、警告、错误状态保留语义色，但饱和度和块面强度低于当前 Bootstrap 默认样式

### 字体

- 保持 Inter 作为主字体，避免引入新的显示型字体造成整体风格漂移
- 标题字重提高，正文维持中性字重
- 辅助标签使用更小字号与更高字距，但不改变文案语言

### 形状与层次

- 卡片采用方正风格，圆角收敛到极小值或接近无圆角
- 使用细边框和浅阴影代替当前较强的 Bootstrap 面板感
- 通过区块标题、弱分隔线、灰阶背景层次建立阅读节奏，而不是依赖大面积纯色标题条

### 动效

- 保留轻量 hover 和 focus 反馈
- 不引入重动画，不改变原有交互节奏

## 页面级设计

### 首页 `index.html`

首页保留当前作为主工作台的定位，不做结构重排。以下模块必须原样保留其功能：

- 全局浮动进度条
- Hero 区
- Google Scholar 导入
- 目标论文输入与别名管理
- 服务层级配置
- API 配置与高级配置折叠区
- 开始分析 / 取消
- 从缓存直接生成报告
- 进度条与实时日志
- SPA 的 Home / Results / Config 面板切换逻辑

#### 首页视觉改造规则

- 当前深色渐变 Hero 改为浅色工作台头图区，保留标题信息，但减少视觉压迫感
- 所有 `agent-card` 统一为白底细边框卡片
- 输入框、下拉框、复选框、开关、折叠按钮改成统一的浅色表单风格
- 论文列表项与别名行要增强可编辑感，但不能像标签输入组件那样重构交互
- 运行进度与日志模块应保持高辨识度，其中日志容器仍可保留深色终端底色

### 配置页 `config.html`

配置页保持现有长表单结构和字段顺序，不改配置能力，只提升阅读层次。

#### 配置页视觉改造规则

- 取消当前强烈的 Bootstrap `card-header bg-success/bg-light` 感
- 每一组配置项转成统一“分区卡片 + 区块标题 + 说明文字”的视觉结构
- `alert`、`badge`、`form-text` 改造成更轻的提示样式
- “已保存”状态与 API 测试结果保留现有行为，但视觉上改成更精细的状态提示

### 任务页 `task.html`

任务页必须维持当前“左日志、右进度与控制”的结构，因为这已经是功能上的自然分区。

#### 任务页视觉改造规则

- 左侧日志区域保留深色终端风格，继续承担高密度输出
- 右侧进度卡、阶段卡、控制卡统一为浅色方正卡片
- 进度条改成更贴近参考稿的细边框浅底轨道 + 蓝色或语义色进度层
- 阶段状态图标、连接状态徽标、控制按钮统一进入新视觉系统

### 结果页 `results.html`

结果页是最接近用户参考稿的页面，但仍应保留现有结果表格和操作方式。

#### 结果页视觉改造规则

- 页面头部改成“结果工作区”的视觉语气，但文案维持中文
- 表格继续保留，用于文件名、类型、大小、时间、操作的密集展示
- 表格外层卡片、标题区、统计提示、空状态和页脚按钮换成参考稿的学术工作台风格
- 文件类型说明区保留，但风格上要从“帮助卡片”统一到整体视觉体系

## 组件层改造策略

### 全局基础层

重点调整以下基础类或基础元素：

- `body`
- `.agent-navbar` / `.agent-navbar-inner` / `.agent-nav-link`
- `.agent-page-content`
- `.agent-footer`
- `.agent-card`
- 表单控件：`input`、`textarea`、`select`、`.form-control`、`.form-select`
- 按钮：`.btn`、`.btn-agent-primary`、`.btn-agent-secondary`、`.btn-agent-danger`、`.btn-agent-sm`
- 提示与状态：`.alert`、`.badge`、进度条相关类
- 表格：`.table`、`.table-responsive`、页脚控制区

### 页面专属层

当全局基础层不足以覆盖时，只允许新增页面专属 class，不应直接依赖过深的 Bootstrap 结构覆盖。优先做法是：

1. 在模板中增加语义清晰的包裹层 class
2. 在 `style.css` 中基于这些 class 写局部样式
3. 尽量避免通过超长选择器硬压 Bootstrap 默认样式

## 数据流与兼容性

本次改造不改变数据流。

- Jinja 模板数据注入方式保持不变
- FastAPI 页面路由与 API 路由保持不变
- `main.js` 负责的 SPA 切换、论文列表编辑、配置加载与保存、结果加载、运行状态更新逻辑保持不变
- `websocket.js` 负责的实时日志与进度更新机制保持不变

设计上的唯一要求是：模板 class 和包裹层变化不能破坏 JS 依赖的 `id`、`data-*`、关键 DOM 结构假设。如果某个 JS 逻辑依赖特定节点存在，则该节点必须保留。

## 错误处理与回退要求

### DOM 兼容

若样式改造需要增加包裹层，必须确认不会影响：

- 通过 `document.getElementById` 获取的节点
- 通过 `querySelector` 匹配的功能节点
- 依赖点击事件代理的容器

### Bootstrap 共存

当前项目仍引入 Bootstrap。新视觉系统应覆盖其默认观感，但不能导致：

- 模态或折叠区失效
- 表单控件交互失效
- 按钮状态不可点击
- 表格溢出滚动异常

如果出现此类问题，应优先保证功能稳定，其次再调视觉一致性。

## 测试与验收

### 手动验收场景

#### 首页

- 能正常输入论文标题并添加到列表
- 能编辑论文标题与别名
- Scholar 导入折叠/展开正常
- 服务层级与高级配置可展开
- 开始分析、取消、缓存生成报告按钮仍存在且可交互
- 日志区域与进度区域正常显示

#### 配置页

- 能正常加载配置
- 输入框、文本域、开关、测试按钮、保存按钮均可操作
- 折叠配置区、条件显示区块正常

#### 任务页

- WebSocket 状态区域可见
- 日志容器可滚动
- 进度条、阶段列表、控制按钮显示正常

#### 结果页

- 结果列表能正常渲染
- 空状态能正常显示
- 刷新和跳转按钮可见
- 表格列对齐与操作按钮不失真

### 视觉验收标准

- 四页的导航、字体、卡片、边框、按钮、输入框属于同一视觉体系
- 整体风格明显更接近用户参考稿，而不是简单换成另一套 Bootstrap 主题色
- 中文文案保持原义，不引入额外英文辅助标题
- 页面在桌面宽度与常见窄屏宽度下均保持可用

## 实施顺序

1. 改造 `base.html` 的全局框架观感
2. 重建 `style.css` 中的全局视觉变量与基础组件样式
3. 对 `index.html` 补充必要包装 class，并完成首页换肤
4. 对 `config.html`、`task.html`、`results.html` 做对应模板包装与局部样式适配
5. 本地运行并逐页检查功能入口是否受影响

## 风险

- 当前模板混合了自定义类与 Bootstrap 类，样式覆盖可能互相干扰
- 首页承载 SPA 与大量动态注入内容，是最容易在视觉改造时误伤 JS 的页面
- 结果页若过度模仿参考稿的卡片化展现，容易越过“只换皮”的边界，因此必须保留表格核心结构

## 结论

本次工作应采用“共享组件换肤”方案：保持现有页面结构、中文文案和功能逻辑不变，统一重做导航、卡片、表单、日志外框、进度与表格的视觉系统，让 CitationClaw 从当前 Bootstrap 工具页观感，升级为更接近学术研究工作台的统一界面。
